# Telegram-бот для чата

Бот отвечает в групповых чатах, если:

- его упомянули через `@bot_username`;
- сообщение начинается с `??`;
- сообщение содержит английское слово (в том числе внутри смешанного русского/английского текста).

Режим зависит от способа вызова:

- при упоминании через `@` или префиксе `??` бот отвечает как обычный умный ассистент;
- на обычное английское сообщение бот работает как носитель английского и преподаватель: даёт краткий, более естественный вариант и 1–3 полезных совета.

Ответы формируются через GigaChat или VseGPT API. Провайдер выбирается одной
переменной `AI_PROVIDER`. Если ключ выбранного провайдера не задан, бот отвечает
тестовым fallback-сообщением, чтобы можно было проверить подключение к Telegram.

## Запуск

Нужен Python 3.10+.

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python bot.py
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe bot.py
```

На Windows автозапуск выполняется через `run_bot.vbs`. В рабочей конфигурации
бот зарегистрирован в Планировщике заданий под именем `Top Tg Bot` и запускается
при входе пользователя в систему. `run_bot.bat` записывает сообщения запуска и
ошибки в локальный файл `bot_autostart.log` (он не попадает в Git). VPN
запускается отдельной задачей v2rayN. Перед запуском бот ждёт локальный прокси
v2rayN на `127.0.0.1:10808` (до 90 секунд), затем запускается в любом случае;
сам бот также повторяет сетевые запросы, если соединение ещё не готово.

В `.env` укажите только секреты:

1. `TELEGRAM_BOT_TOKEN` — токен от `@BotFather`.
2. Для GigaChat: `GIGACHAT_CREDENTIALS` — Authorization Key.
3. Для VseGPT: `VSEGPT_API_KEY` — ключ из [кабинета VseGPT](https://vsegpt.ru/User/API).

Все остальные параметры находятся в `config.json`: провайдер и модели, промты,
лимиты контекста и памяти, файлы памяти и напоминаний, часовой пояс и журналирование.
`telegram_proxy_url` задаёт SOCKS5/HTTP-прокси для Bot API и long polling; по
умолчанию это локальный SOCKS5 Happ `socks5://127.0.0.1:10808`.
Например, лимиты контекста задаются полями `soft_context_limit`,
`hard_context_limit`, `keep_last_messages` и `max_english_history_messages`.

## Анализ изображений через VseGPT

При `AI_PROVIDER=vsegpt` бот умеет анализировать изображения:

- отправьте фото с подписью `?? что на нём?` — получить анализ изображения;
- фото с подписью `/analyze ваш вопрос` работает так же.

Модель анализа настраивается через `vsegpt_vision_model` в `config.json`. Для текстовых и
vision-ответов установлен лимит `vsegpt_max_tokens=200`, чтобы
не резервировать большой бюджет на ответ.

## Память и контекст

В обычном режиме бот хранит текущий рабочий контекст каждого чата в локальном
`context_history.json`, поэтому перезапуск не сбрасывает ход разговора. Полная
история активного контекста (сообщения пользователей и ответы бота) восстанавливается
при следующем запуске. Сжатые общие и пользовательские факты дополнительно хранятся в
`memory.json`. В обычный API-запрос уходит не больше `soft_context_limit` последних
сообщений, а полная рабочая история сохраняется для последующего сжатия. Если три
последних запроса пришли от одного пользователя, контекст выбирается только из его
ветки. При `hard_context_limit` отдельный запрос получает полную текущую память и всю
историю контекста, возвращает объединённую память обычным текстом, после чего она
обновляется и остаются как минимум последние `keep_last_messages`; если хвост
начинается с ответа бота, сохраняется и относящаяся к нему реплика пользователя.
Факты, которых нет в новой истории, не удаляются.
Английский режим память не получает и использует только
`max_english_history_messages` сообщений. Эти значения редактируются в `config.json`.

В `memory.json` у каждого чата и пользователя есть два раздела: `immutable.facts`
для фактов, которые можно вписать вручную и которые модель не изменяет, и
`mutable.facts` для фактов, добавляемых моделью при сжатии. В контекст передаются
оба раздела без повторяющихся формулировок, но запрос памяти записывает только в
`mutable`. В групповом ответе модель получает профиль текущего автора, общие факты
чата и отдельные профили остальных участников. Память помечается как справочная:
модель не должна упоминать её без прямой связи с текущим сообщением.

В `chat_types` хранится тип чата. В личном диалоге запрос получает два набора:
локальную память личного чата и отдельные блоки памяти этого пользователя из каждого
группового чата. Эти блоки только склеиваются в запросе с указанием `chat_id` и не
объединяются между собой. В групповом чате передаётся только память этого чата;
личная память пользователя и память других групп туда не попадают.

## Журнал запросов к API

При `api_journal_enabled: true` бот сохраняет в `api_journal.jsonl` точные сообщения,
которые получил AI-провайдер, и только текст его ответа. API-ключи, заголовки и URL
не записываются. Журнал хранится локально и ограничен `api_journal_max_entries`.
Команда `/log` показывает последние пять запросов текущего чата, `/log 10` — последние
десять. Для анализа изображений полный data URL может быть большим; в Telegram он
обрезается, а в локальном журнале сохраняется полностью.

## Напоминания

Напоминание создаётся командой `/н` со свободным текстом: например, `/н напомни
завтра вечером позвонить другу` или `/н через пару часов проверить задачу`. Отдельный
запрос к модели определяет время и смысл задачи. Активные задачи хранятся
в `reminders.json`, поэтому не пропадают после перезапуска. В момент срабатывания
бот делает отдельный запрос только с текстом напоминания и отправляет короткий
результат в исходный чат. Часовой пояс задаётся через `BOT_TIMEZONE` и по умолчанию
равен `Europe/Moscow`.

В обычном режиме можно написать без команды: `напомни завтра в 15:00 позвонить
врачу`. Основная модель сама вызывает native tool `create_reminder`, который
переиспользует тот же разбор времени, `reminders.json` и действующий планировщик.
Tool `web_search` выполняет интернет-поиск и возвращает модели заголовки, ссылки и
краткие описания результатов. Registry инструментов находится в `tools_registry.py`.
Дополнительные правила tools склеиваются с `system_prompt` во время запроса и не
меняют prompt из `config.json`; режим проверки английского tools не получает.
Вместе с native tool call модель генерирует короткий `status_text`, который бот сразу
отправляет в чат без отдельного API-запроса. Финальный ответ после результата tool
формируется обычным следующим шагом tool-calling цикла. После отправки финального
ответа временные сообщения со статусами удаляются из Telegram-чата.
Если в группе ответить на сообщение бота через Reply, он отвечает без `??` и `@`.

Если Python ещё не установлен, поставьте Python 3.10+ и включите опцию
`Add Python to PATH` в установщике.

## Вакансии из HH.ru и Habr Career

Парсер работает без запросов к AI: получает вакансии из HH API (при ответе
`403` автоматически переключается на HTML-выдачу HH) и страницы Habr Career,
фильтрует их локально и хранит уже просмотренные объявления в `vacancies.json`.

Фильтр задаётся в `config.json`:

```json
"vacancy_keywords": ["python", "backend"],
"vacancy_required_keywords": [],
"vacancy_excluded_keywords": ["senior"],
"vacancy_locations": ["Екатеринбург", "удалённо"],
"vacancy_remote_only": false,
"vacancy_min_salary": 100000,
"vacancy_max_age_hours": 72
```

`vacancy_keywords` работает по принципу «хотя бы одно слово», а
`vacancy_required_keywords` — «все слова обязательны». После изменения
`config.json` перезапусти бота.

Команды в Telegram:

- `/vacancies` — разовая проверка и первые найденные вакансии;
- `/vacancies on` — включить автоматические уведомления;
- `/vacancies off` — выключить уведомления;
- `/vacancies status` — показать текущую настройку.

Первый запуск подписки только создаёт базу уже существующих вакансий и не
засоряет чат старой выдачей. Новые объявления проверяются раз в 30 минут.

В текущей конфигурации уведомления закреплены за Telegram chat ID
`1863437123` и включаются автоматически при запуске. Пользователь должен хотя
бы один раз открыть бота и отправить ему `/start`.

## Важная настройка Telegram-группы

Чтобы бот видел обычные сообщения в группе и мог определять английский текст, отключите Privacy Mode у бота через `@BotFather`:

`/setprivacy` → выбрать бота → `Disable`.

После этого добавьте бота в группу. В противном случае Telegram обычно передаёт ему только команды и сообщения с упоминанием.

## Настройка логики

Тексты системных инструкций меняются через `SYSTEM_PROMPT` и `ENGLISH_COACH_PROMPT`. Поэтому можно отдельно настроить общий режим и режим проверки английского.
