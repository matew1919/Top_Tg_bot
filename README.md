# Telegram-бот для чата

Бот отвечает в групповых чатах, если:

- его упомянули через `@bot_username`;
- сообщение начинается с `??`;
- пользователь ответил на сообщение самого бота;
- сообщение содержит английское слово (в том числе внутри смешанного русского/английского текста).

Для медиа действуют те же правила: в группе добавьте `??` или упоминание бота
в подпись либо ответьте на сообщение бота. В личном чате медиа можно отправлять без
триггера.

До обращения к модели и обработки медиа бот пропускает короткие реакции с отдельными
словами `норм`, `кайф` или смехом `ахах…`, если в тексте меньше двух пробелов.
Перед подсчётом убираются упоминание бота и `??`, пробельные разделители нормализуются:
`норм` и `ну норм` пропускаются, `норм, расскажи подробнее` обрабатывается.
Фильтр действует при Reply на бота, в личке и в подписях к медиа.
Текст цитируемого сообщения сам по себе фильтр не включает. Другие слова в список
не добавлены; шаблоны находятся в `IGNORED_MESSAGE_PATTERNS` в `bot.py`.

Режим зависит от способа вызова:

- при упоминании через `@` или префиксе `??` бот отвечает как обычный умный ассистент;
- на обычное английское сообщение бот работает как носитель английского и преподаватель: даёт краткий, более естественный вариант и 1–3 полезных совета.

Ответы формируются через GigaChat или VseGPT API. Провайдер выбирается одной
переменной `AI_PROVIDER`. Если ключ выбранного провайдера не задан, бот отвечает
тестовым fallback-сообщением, чтобы можно было проверить подключение к Telegram.

## Запуск

Нужен Python 3.10+.

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python bot.py
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe bot.py
```

На Windows автозапуск выполняется через `run_bot.vbs`. В рабочей конфигурации
бот зарегистрирован в Планировщике заданий под именем `Top Tg Bot` и запускается
при входе пользователя в систему. `run_bot.bat` записывает сообщения запуска и
ошибки в локальный файл `bot_autostart.log` (он не попадает в Git). VPN
запускается отдельной задачей v2rayN. Перед запуском бот ждёт локальный прокси
v2rayN на `127.0.0.1:10808` (до 90 секунд), затем запускается в любом случае;
сам бот также повторяет сетевые запросы, если соединение ещё не готово.

В `.env` укажите только секреты:

1. `TELEGRAM_BOT_TOKEN` — токен от `@BotFather`.
2. Для GigaChat: `GIGACHAT_CREDENTIALS` — Authorization Key.
3. Для VseGPT: `VSEGPT_API_KEY` — ключ из [кабинета VseGPT](https://vsegpt.ru/User/API).

Все остальные параметры находятся в `config.json`: провайдер и модели, промты,
лимиты контекста и памяти, файлы памяти и напоминаний, часовой пояс, доступ владельца,
ограничение частоты запросов, журналирование и автозапуск парсера вакансий.
`telegram_proxy_url` задаёт SOCKS5/HTTP-прокси для Bot API и long polling. В рабочей
конфигурации значение пустое: Telegram доступен напрямую, а локальный прокси давал
таймауты. Если прямой доступ пропадёт, здесь можно снова указать адрес прокси.
Раз в 30 секунд бот проверяет собственное соединение через `getMe`, сохраняя его
для следующего ответа. При сетевом сбое проверка повторяется через 5 секунд;
сообщения в чаты не отправляются. Подключение ограничено 4 секундами, ожидание
ответа на обычный запрос — 10 секундами; у long polling отдельный длинный таймаут.
Например, лимиты контекста задаются полями `soft_context_limit`,
`hard_context_limit`, `keep_last_messages` и `max_english_history_messages`.

## Фото, аудио, видео и ответы на сообщения

При `AI_PROVIDER=vsegpt` мультимедиа обрабатывается без отдельной команды `/analyze`.
В личном чате достаточно просто отправить файл или ссылку. В группе используйте обычный
вызов бота: `??` или `@bot_username` в подписи к медиа; также работает ответ на сообщение
бота.

- фото и изображения, отправленные как файл;
- голосовые сообщения и обычные аудиофайлы;
- видео, видеосообщения, анимации и видеофайлы;
- ссылки `youtube.com`, YouTube Shorts и `youtu.be`;
- медиа из сообщения, на которое пользователь ответил с упоминанием бота.

Фото сразу передаётся мультимодальной модели вместе с обычным системным промтом,
памятью и историей, поэтому итоговый ответ сохраняет личность бота. Для аудио сначала
выполняется транскрибация. Из видео локально извлекаются компактная аудиодорожка и до
`media_max_frames` равномерных ключевых кадров; готовое видео целиком модели не
передаётся. YouTube загружается только с разрешённых доменов, без cookies и плейлистов.

Модели задаются через `vsegpt_multimodal_model` и
`vsegpt_transcription_model`. Ограничения управляются полями `media_max_bytes`,
`media_max_duration_seconds`, `media_max_frames`, `media_max_transcript_chars` и
`media_processing_timeout`. Суммарную нагрузку одного сообщения ограничивают
`media_max_files_per_turn`, `media_max_turn_bytes` и
`media_max_image_payload_bytes`. Облачный Telegram Bot API скачивает файлы размером не
более 20 МБ, поэтому значение `media_max_bytes` программно ограничено этим пределом.
`imageio-ffmpeg` поставляет FFmpeg вместе с Python-зависимостью, отдельная системная
установка FFmpeg не требуется. Видеоссылки загружает `yt-dlp`; готовые русские
субтитры имеют приоритет, затем английские, и только без них вызывается STT.

Если пользователь упоминает бота, отвечая на чужое сообщение, в запрос добавляются
автор, текст/подпись и поддерживаемое вложение исходного сообщения. Telegram сам
ограничивает вложенную reply-цепочку одним уровнем. Фотоальбомы объединяются по
`media_group_id`, чтобы бот не отвечал на каждый кадр отдельно.

## Память и контекст

В обычном режиме бот хранит текущий рабочий контекст каждого чата в локальном
`runtime/context_history.json`, поэтому перезапуск не сбрасывает ход разговора. Полная
история активного контекста (сообщения пользователей и ответы бота) восстанавливается
при следующем запуске. Сжатые общие и пользовательские факты дополнительно хранятся в
`runtime/memory.json`. В обычный API-запрос уходит не больше `soft_context_limit` последних
сообщений, а полная рабочая история сохраняется для последующего сжатия. Если три
последних запроса пришли от одного пользователя, контекст выбирается только из его
ветки. При `hard_context_limit` отдельный запрос получает полную текущую память и всю
историю контекста, возвращает объединённую память обычным текстом, после чего она
обновляется и остаются как минимум последние `keep_last_messages`; если хвост
начинается с ответа бота, сохраняется и относящаяся к нему реплика пользователя.
Факты, которых нет в новой истории, не удаляются.
Английский режим память не получает и использует только
`max_english_history_messages` сообщений. Эти значения редактируются в `config.json`.

В файле `runtime/memory.json` у каждого чата и пользователя есть два раздела: `immutable.facts`
для фактов, которые можно вписать вручную и которые модель не изменяет, и
`mutable.facts` для фактов, добавляемых моделью при сжатии. В контекст передаются
оба раздела без повторяющихся формулировок, но запрос памяти записывает только в
`mutable`. В групповом ответе модель получает профиль текущего автора, общие факты
чата и отдельные профили остальных участников. Память помечается как справочная:
модель не должна упоминать её без прямой связи с текущим сообщением.

В `chat_types` хранится тип чата. В личном диалоге запрос получает два набора:
локальную память личного чата и отдельные блоки памяти этого пользователя из каждого
группового чата. Эти блоки только склеиваются в запросе с указанием `chat_id` и не
объединяются между собой. В групповом чате передаётся только память этого чата;
личная память пользователя и память других групп туда не попадают.

## Журнал запросов к API

Журнал по умолчанию выключен. При `api_journal_enabled: true` он пишет в
`runtime/api_journal.jsonl` только технические метаданные: время, провайдера, модель,
тип запроса, количество сообщений, длину ответа, время генерации и число обращений
к API. Текст переписки появляется в
журнале только при отдельном включении `api_journal_include_content`; бинарные data URL
всё равно заменяются безопасной меткой. API-ключи и заголовки не записываются.
Команда `/log [N]` доступна только владельцу бота в личном чате.

## Напоминания

Напоминание создаётся командой `/н` со свободным текстом: например, `/н напомни
завтра вечером позвонить другу` или `/н через пару часов проверить задачу`. Отдельный
запрос к модели определяет время и смысл задачи. Активные задачи хранятся
в `runtime/reminders.json`, поэтому не пропадают после перезапуска. В момент срабатывания
бот делает отдельный запрос только с текстом напоминания и отправляет короткий
результат в исходный чат. Часовой пояс по умолчанию задаётся полем `timezone` в
`config.json`, а пользователь может выбрать свой через `/timezone Europe/Moscow`.

В обычном режиме можно написать без команды: `напомни завтра в 15:00 позвонить
врачу`. Основная модель сама вызывает native tool `create_reminder`, который
переиспользует тот же разбор времени, `runtime/reminders.json` и действующий планировщик.
Tool `web_search` выполняет интернет-поиск и возвращает модели заголовки, ссылки и
краткие описания результатов. Registry инструментов находится в `tools_registry.py`.
В обычном текстовом диалоге оба инструмента доступны без ключевых слов: модель сама
решает, когда искать факты или рекомендации и когда выполнить просьбу о напоминании.
В ответах на сторонние сообщения и в текстовых результатах обработки медиа доступен
поиск, а создание напоминаний отключено. Запросы с изображениями идут через отдельную
мультимодальную модель без инструментов. Поиск может добавить время к ответу.
Дополнительные правила tools склеиваются с `system_prompt` во время запроса и не
меняют prompt из `config.json`; режим проверки английского tools не получает.
Вместе с native tool call модель генерирует короткий `status_text`, который бот сразу
отправляет в чат без отдельного API-запроса. Финальный ответ после результата tool
формируется обычным следующим шагом tool-calling цикла. После отправки финального
ответа временные сообщения со статусами удаляются из Telegram-чата.
Ожидание отправки промежуточного статуса ограничено 3 секундами, удаления — 2 секундами.
Поиск сначала пробует DuckDuckGo, затем резервные источники; на весь поиск выделено
8 секунд, на один источник — до 3 секунд. Таймаут возвращается модели как ошибка
инструмента. Время доставки финального ответа отдельно записывается в локальный лог.
Если в группе ответить на сообщение бота через Reply, он отвечает без `??` и `@`.

## Управление и приватность

В `bot_owner_ids` перечисляются Telegram ID владельцев. Только они могут выполнять
`/status`, `/log` и `/vacancies`, причём лишь в личном чате с ботом. `/status` показывает
доступность AI, планировщика, парсера и число проблемных напоминаний. Ошибки обработчиков
и фоновых задач записываются только в локальный лог, без служебных уведомлений в Telegram.

Команды пользователя:

- `/reminders` — список своих напоминаний в текущем чате;
- `/cancel ID` — отмена своего напоминания;
- `/snooze ID минуты` — перенос своего напоминания;
- `/memory` — просмотр своей сохранённой памяти;
- `/forget confirm` — удаление личной памяти и своих реплик из рабочего контекста;
- `/timezone Зона` — персональный часовой пояс.

Рабочие JSON-файлы находятся в каталоге `runtime/`, создаются атомарно и сохраняют
последнюю резервную копию `.bak`. Они исключены из Git. При первом запуске старые
файлы из корня проекта автоматически копируются в `runtime/`, поэтому существующие
напоминания и память не пропадут. Чтобы не перегружать API, действует лимит запросов
на пользователя и общий лимит одновременно выполняемых AI/медиа-задач.

## Парсер вакансий

Парсер отделён от Telegram-обработчиков: получение и фильтрация находятся в
`vacancy_parser.py`, а расписание и доставка — в `vacancy_monitor.py`. Он не вызывает
языковую модель и запускается вместе с ботом при `vacancy_autostart: true`.
Параметры поиска находятся в `vacancy_config.json`: источники, ключевые и запрещённые
слова, удалённый формат, давность, интервал и `target_chat_id`.

При первом запуске текущая выдача становится базой и не засыпает чат старыми
вакансиями. Новая вакансия помечается отправленной только после успешной доставки в
Telegram, поэтому временный сбой не приводит к потере уведомления. Если один источник
недоступен, второй продолжает проверяться; если недоступны все, ошибка видна в статусе
и монитор автоматически повторит запуск.

HH по умолчанию читается с публичной страницы (`hh_api_enabled: false`), потому что
его API может стабильно возвращать 403. Источники запрашиваются параллельно, временные
сетевые сбои повторяются согласно `source_attempts`. После `source_failure_alert_after`
неудачных проверок подряд сбой и последующее восстановление фиксируются в локальном
логе; уведомления об этом в Telegram отключены. Последний успешный запуск и состояние каждого источника
сохраняются в `runtime/vacancy_state.json` и доступны после перезапуска через
`/vacancies status`.

## Автозапуск на macOS

Рабочий Mac использует LaunchAgent из `macos/com.matvei.top-tg-bot.plist`: бот запускается после
входа пользователя в систему и автоматически поднимается снова после аварийного
завершения. Агент запускает `.venv/bin/python bot.py`, передавая путь к секретному
`.env` через переменную `BOT_ENV_FILE`. Основной журнал пишется с ротацией в
`runtime/bot_runtime.log`; диагностические stdout/stderr launchd находятся рядом.

Проверить состояние можно командой `launchctl print gui/$(id -u)/com.matvei.top-tg-bot`.
Остановить агент — `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.matvei.top-tg-bot.plist`.

Управление из личного чата владельца:

- `/vacancies status` — состояние и последний результат;
- `/vacancies check` — немедленная проверка;
- `/vacancies show` — показать подходящую текущую выдачу без изменения базы;
- `/vacancies off` и `/vacancies on` — пауза и продолжение.

Одновременно разрешён только один экземпляр мониторинга. Если старый отдельный
`vacancy_watcher.py` ещё работает, встроенный монитор увидит блокировку и не запустит
вторую копию. После перехода на встроенный режим отдельный watcher следует остановить.

## Проверка изменений

Для локального прогона:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Те же тесты автоматически выполняются в GitHub Actions при каждом push и pull request.
Они проверяют контекст, напоминания, безопасное хранение, лимиты, медиа, фильтры
вакансий и отсутствие потери уведомления при ошибке Telegram.

Если Python ещё не установлен, поставьте Python 3.10+ и включите опцию
`Add Python to PATH` в установщике.

## Важная настройка Telegram-группы

Чтобы бот видел сообщения с префиксом `??` без упоминания и мог определять обычный
английский текст в группе, отключите Privacy Mode у бота через `@BotFather`:

`/setprivacy` → выбрать бота → `Disable`.

После изменения настройки пере-добавьте бота в группу. При включённом Privacy Mode
используйте `@bot_username` или ответ боту: такие сообщения Telegram ему доставляет.

## Настройка логики

Тексты системных инструкций меняются через `SYSTEM_PROMPT` и `ENGLISH_COACH_PROMPT`. Поэтому можно отдельно настроить общий режим и режим проверки английского.
